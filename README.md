# AI Research Assistant

**基于 RAG 与大语言模型的智能科研助手系统**

一个面向科研论文阅读与问答的实践项目。系统将 PDF 文本解析、文本切分、向量检索和大语言模型生成结合起来，支持围绕指定论文进行问答，并展示回答所依据的原文片段。

> **项目阶段：** 原型开发与检索质量优化阶段。当前已实现基础 RAG 问答、Streamlit 网页交互、论文入库状态展示，以及指定 PDF 页码范围的分批总结。检索准确性、边界情况和完整性仍在持续验证中。

## 项目目标

科研论文通常包含大量专业术语、技术方法和实验结论。直接将整篇论文输入大语言模型可能受到上下文长度限制，也不利于追溯答案来源。

本项目尝试构建一个基于检索增强生成（Retrieval-Augmented Generation，RAG）的科研助手：先从论文中检索相关原文，再将检索结果交给大语言模型回答问题，并保留论文文件名、PDF 页码和文本片段，帮助用户核对回答依据。

当前主要面向 PDF 论文问答与阅读辅助；多智能体协作属于项目后续探索方向，尚不应视为已完成的功能。

## 当前功能

### 已实现的基础功能

- **PDF 上传与保存：** 通过 Streamlit 网页上传 PDF，并保存至 `data/papers/`。
- **论文文本提取：** 使用 PyMuPDF 按 PDF 页面提取文本，并记录 PDF 页码。
- **文本切分：** 使用 `RecursiveCharacterTextSplitter` 将文本切分为有重叠的 Chunk。
- **向量生成：** 使用 `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` 将文本转换为 Embedding。
- **向量数据库：** 使用 ChromaDB 持久化保存文本、向量和元数据。
- **论文入库状态：** 显示本地论文是否已入库及对应 Chunk 数量。
- **指定论文问答：** 可选择一篇已入库的论文进行 RAG 问答。
- **检索证据展示：** 展示检索到的原文片段、论文文件名、PDF 页码和可用时的检索距离。
- **会话内聊天历史：** 在当前 Streamlit 会话中显示历史问题、回答及对应的检索证据。
- **指定 PDF 页码范围总结：** 识别诸如“第 20–30 页讲了什么”的问题，获取该范围内已入库的文本块，按每批 5 个 Chunk 分批总结，再合并各批摘要。
- **普通 LLM 问答：** 网页提供普通大语言模型问答模式，与基于论文检索的 RAG 模式区分。

以上功能状态依据当前开发记录整理。长文本总结已有运行成功反馈，但尚未完成系统性准确率评估和全部边界测试。

## 技术栈

| 模块 | 技术 | 用途 |
|---|---|---|
| 编程语言 | Python | 项目主要开发语言 |
| PDF 解析 | PyMuPDF (`pymupdf`) | 提取 PDF 页面文本 |
| 文本切分 | LangChain Text Splitters | 将长文本切分为 Chunk |
| Embedding | Sentence Transformers | 生成文本向量 |
| Embedding 模型 | `paraphrase-multilingual-MiniLM-L12-v2` | 将问题和论文片段映射到向量空间 |
| 向量数据库 | ChromaDB | 保存、过滤和检索论文文本块 |
| 大语言模型调用 | 项目内 `llm_client.py` | 统一调用模型并生成回答 |
| Web 应用 | Streamlit | 提供上传、论文选择、问答和证据展示界面 |
| 版本管理 | Git / GitHub | 代码版本管理 |

## 系统流程

### 论文入库流程

```text
上传 PDF
   ↓
PyMuPDF 按页提取文本
   ↓
RecursiveCharacterTextSplitter 切分文本
   ↓
Sentence Transformers 生成 Embedding
   ↓
附加文件名、PDF 页码、paper_id 等元数据
   ↓
ChromaDB 持久化保存
```

### 普通 RAG 问答流程

```text
输入科研问题
   ↓
将问题转换为 Embedding
   ↓
ChromaDB 进行 Top-K 语义检索
   ↓
整理相关原文与来源信息
   ↓
调用大语言模型生成回答
   ↓
展示回答和检索证据
```

### 指定页码范围总结流程

```text
输入指定页码范围的问题
   ↓
识别页码范围并按元数据筛选
   ↓
获取范围内已入库的文本块
   ↓
每批 5 个 Chunk 分别总结
   ↓
合并各批摘要
   ↓
生成综合回答并展示来源
```

```bash
cd AI_Research_Assistant
```

将 `<YOUR_GITHUB_REPOSITORY_URL>` 替换为实际 GitHub 仓库地址。

Windows PowerShell：

```bash

```

此外，`llm_client.py` 可能依赖用于访问模型服务的客户端库。请以项目实际的 `llm_client.py` 和依赖文件为准补齐依赖。

## 运行项目

在项目根目录中运行：

```bash
streamlit run app.py
```

Streamlit 启动后，根据终端提示打开本地网页地址。

也可以直接运行 RAG 脚本进行基础测试：

```bash
python rag.py
```

`rag.py` 中的 `PDF_PATH` 是直接运行该脚本时使用的默认测试 PDF 路径。通过网页上传论文时，网页会把上传文件的实际路径传给 `build_database()`。

首次使用时，需要先在网页侧栏上传 PDF，再点击“开始建立知识库”。完成入库后，选择对应论文进入 RAG 问答模式。

## 使用方法

1. 启动 Streamlit 网页。
2. 在侧栏上传 PDF 论文。
3. 点击“开始建立知识库”，等待文本提取、向量生成和入库完成。
4. 在论文选择框中选择要查询的论文。
5. 选择 **RAG 论文问答** 模式并输入科研问题。
6. 查看回答下方的“查看检索证据”，核对原文、文件名和 PDF 页码。
7. 如果需要总结指定页码范围，可以尝试提问，例如：

   `这篇文章第20-30页讲了什么？`

普通问题使用 Top-K 语义检索；指定页码范围的问题会获取范围内已入库的 Chunk 并分批总结。

## 核心实现说明

### Chunk 切分

当前切分参数为：

- `chunk_size=1000`
- `chunk_overlap=200`

重叠区域用于降低切分边界导致上下文断裂的风险。当前参数属于初始实现，尚未通过系统实验确定为最优配置。

### 向量检索

普通问答默认使用 `top_k=3`。Top-K 控制返回给模型的候选文本块数量，但语义相似度排序并不保证所有关键证据都被召回。当前项目仍需评估候选数量、检索排序及参考文献等文本噪声的影响。

### 元数据

入库时保存的元数据包括：

- `source`：源文件路径；
- `page`：PDF 页码；
- `paper_id`：根据 PDF 文件内容生成的标识；
- `filename`：论文文件名。

这些字段支持论文过滤、页码范围检索及来源展示。

### 长文本总结

指定页码范围时，系统将取出的文本块按每批 5 个进行总结，再将中间摘要合并。该方案已在开发过程中运行成功，但仍需进一步检查摘要遗漏、引用准确性、超长范围和模型服务异常等情况。

## 当前限制

- **检索质量仍在优化：** 普通 Top-K 检索可能返回作者简介或参考文献等干扰内容，相关正文不一定排在前列。
- **尚未进行系统性评估：** 目前没有经过完整标注的测试集，也没有足够数据证明检索准确率或回答质量已提升。
- **PDF 提取受源文件影响：** 扫描版 PDF、复杂双栏排版、公式和图表可能无法被当前文本提取流程完整表达。
- **页码范围依赖元数据：** 只会处理已入库且页码元数据落在指定范围内的文本块，不能保证每一页都提取成功。
- **分批摘要可能损失细节：** 中间摘要和最终合并可能遗漏技术条件、数值或限制。
- **会话历史范围有限：** 当前历史记录主要由 Streamlit `st.session_state` 保存，不应视为跨重启的永久存储。
- **多智能体尚未完成：** 当前可确认的主要实现是单次 RAG 检索与大语言模型回答流程。多智能体协作仍属于后续开发方向。

## 后续计划

1. 建立固定科研测试问题集，记录 Top-K 的原文、页码和距离，形成可复现的检索基线。
2. 分析作者简介、参考文献等文本噪声对检索结果的影响。
3. 对比不同候选数量与排序策略；在有测试依据后评估是否引入 Reranker。
4. 验证指定页码范围总结的覆盖度、引用准确性及异常处理。
5. 完善论文重复入库、更新、删除和旧 Chunk 清理机制。
6. 固定依赖版本、完善 README 与测试文档，并在检索质量稳定后继续探索多智能体协作。

## 安全说明

- 不要将 API Key、访问令牌或其他密钥写入公开代码仓库。
- 不要在未确认论文许可的情况下公开上传受版权保护的全文。
- 公开仓库前检查 `.gitignore`，避免提交 `.venv/`、缓存、日志、个人配置、密钥和不应公开的数据。
- 模型生成的答案应与检索原文交叉核对；本项目旨在辅助科研阅读，不应将模型回答直接当作未经核验的事实。
